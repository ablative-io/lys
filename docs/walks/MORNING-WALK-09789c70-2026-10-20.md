## 3. Setter issues Newbie's first certificate (AGENTS-016 R4)

**Who:** Setter, tool **change**, `POST /agents/<newbie id>/certificates`, body `{operation, request}`
(certificates_issue.rs:54-58 `IssueBody`): `request` is a PKCS#10 certificate request, **DER, standard base64**
(certificates_issue.rs:247-251: "request is not standard base64" / "the request was refused"), proving Newbie's
public key.

**Code:** openapi_table.rs:386 ("or, by the agent that registered it, its first certificate alone");
certificates_issue.rs:282-346 `first`: the registrar must be the caller (:303 `agent_not_yours`), the caller's
`agent.create` from Newbie's person is read **live** at that moment (:308-323; revoked since or never held is
`agent_create_revoked`, error_agent_acts.rs:37-39: "a person issues its certificate"), and Newbie must hold no
certificate, issued or withdrawn (:346 `certificate_not_first`, 409).

**What Tom sees:** Newbie's file, Certificates tab, one certificate issued by Setter, Tom responsible
(certificates_issue.rs:280-281).

**TOM** Nothing in Lys makes Newbie's key or its request. The key is `lys key generate` on some computer (cli.rs:343-346),
the request is `lys ca request --key <key file> --subject <name> --out <pem>` (cli/ca.rs:18-33), and that command writes
**PEM** while the route takes **base64 DER**, so Setter converts by hand before it can post. Newbie's private key then
sits wherever Setter made it; nothing moves it to the computer Newbie will run on. This is the hand-made key and file
in the walk. (The runner's own key writing at lys-runner/src/seat_owner/sessions.rs:190-212 is the seat owner's server
key, not Newbie's.)
